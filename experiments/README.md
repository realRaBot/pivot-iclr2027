# Experiment harness

`hyperiv_price_iv_aux/scripts/bench_differentiable_iv.py` is fully synthetic
and requires no licensed data.

The two training scripts expect prepared parquet files with one row per option
and these columns:

```text
date, is_ref, log_moneyness, tau, sigma_star,
F, K, r, is_call, mid, vega_star
```

Run `make_synthetic_fixture.py` to create a small fixture under
`hyperiv_price_iv_aux/prepared/`. Raw WRDS/OptionMetrics rows are intentionally
excluded; only aggregate manifests are published.

## Controls and reproduction scope

The supplied scripts support three complementary checks:

- `train.py`: compare `price_rt_aux` with `price_direct_iv_aux` using the same
  seeds, weights, and gate. `--equiv-check-every 100` probes their loss and
  gradient agreement. This IV-output control does not establish that an
  inverse is necessary when the model already predicts IV.
- `train_price_output.py`: the model predicts prices, and the IV objective
  requires inversion. Compare `pivot_iv` with `jackel_ift_iv` to hold the
  forward solver fixed while changing the backward contract. `unrolled_iv`
  and `generic_ift_iv` also change the forward solver.
- `bench_differentiable_iv.py`: matched synthetic forward/backward timing,
  errors, invalid-input accounting, and finite-difference validation.

`../slurm/matched_seed_campaign.sbatch` preserves the supplied 100-epoch
roundtrip/direct campaign for seeds 1, 2, and 3, with both auxiliary weights
0.1 and gate threshold 1e-6. It expects licensed `spx_1day` prepared files.
The public synthetic smoke commands in the root README are independent of
that dataset. Configure the scheduler account and partition for your system.

## Supplied aggregate results

`../results/` contains existing summaries, not results generated by the
installation or smoke commands. The systems summary records a GH200 run;
CPU timings are not comparable. The price-output summary records three seeds
and exposes failures of the same-forward generic-IFT control. No raw run logs
or licensed rows accompany these summaries, so their numerical claims cannot
be independently reconstructed from the repository alone. The synthetic
fixture validates the pipeline, not the reported empirical performance.

Run outputs, generated fixtures, and tracking logs are ignored by Git.
Experiment tracking is disabled by default.
